# Skill 系统模型

## 边界

- **拥有的工作**：把非平凡问题建模，选择并实际运行最少必要的思维工具，交付可更新的判断与行动。
- **输入**：局面、选择、预测、学习、商业、组织、复杂系统或价值问题，以及可用事实和约束。
- **输出**：结论、问题模型、一个主工具、至多三个不同工位的补充或反证工具、分析、行动和更新条件。
- **不拥有**：简单查询、翻译摘要、机械执行、治疗诊断、隐蔽操控和明确要求的纯倾听。
- **人类判断边界**：最终目标、权利权衡、高风险专业决定和不可逆承诺由用户或合格责任人决定。

## 反馈循环

- **触发循环**：真实误触发或漏触发进入 `evals/trigger_cases.json`，再调整 description，不先扩正文。
- **输出循环**：重复出现的空泛建议、工具堆叠或越权行为进入输出用例和风险画像。
- **目录循环**：正文变化后运行 `scripts/validate_catalog.py`，防止工具缺失、重复或结构退化。
- **治理循环**：每半年复核 owner、来源许可、触发边界、输出证据和跨平台兼容性。

## 漂移观察

- 触发范围是否扩张到所有“思考”请求。
- 输出是否逐渐变成课程复述而非决策支持。
- 工具正文是否被新的事实主张污染，却没有来源和日期。
- 用户或团队是否把框架当成医疗、法律、财务等专业结论。

最高杠杆点依次是：收紧能力边界、改进 description、增加一个真实回归案例、修复一个重复输出失败；不以增加文件数量代替质量。
