# 独立评审场景

用于 skill 维护时的试读或执行评估。场景与判据不是已通过的模型输出；执行结果另行记录，技术 fixture 不能替代真实创作验收。

## 已有音乐与画布

请求：“已有一首 64 秒配乐和可 seek 的 p5 工程，做一个完整故事视频，保留原风格。”

观察是否复用声音与成熟渲染器、规划行动和后果、定义稳定实体、按实际拍点而非任意场景比例调度；不强制迁移 HyperFrames、调用 TTS、加入 SFX 或统一纸纹。验实际 MP4 与声音，保留原工程。

## 竖屏旁白缺少细粒度 cue

请求：“做一个 45 秒竖屏视频，解释抓阄放回与不放回为什么影响后续概率。只要视频。两段已有旁白是 12.4 和 21.2 秒，没有句/词 boundary。”

观察是否区分已有音频与新生成、把静音或编辑决定计入实际 45 秒音轨、按已知段级事件或明示估计安排动作；不会捏造词边界。明示等可能、已观察结果与剩余组成，区分条件概率和未观察结果的边际概率。按竖屏重排，不照搬横屏 W/H 与字幕坐标。

## HyperFrames 首帧与异步资源

请求：“已有 Canvas 接到 HyperFrames，第一张截图空白，第二次才正常；不要改变画风。”

观察是否核对本期版本与实际资源/字体 ready、串行 seek 和框架等待契约，区分公开接口与内部兼容 hook；不盲目覆盖 runtime waiter，不用主体运动掩盖竞态。修复后比首帧与同时间冷/热、顺序/乱序状态，不虚构桥接已执行。

## 不变主体被覆盖

请求：“两个灰块移动时必须保持相同颜色，现有检查只读它们的中心像素。”

观察是否检查实际主体内部与边界、前中后状态及绘制层次；不把中心同色或有损 MP4 的数值当完整无损证据。修复后重新编码并复查当前影片，不沿用旧关键帧。

## 只做局部视觉审阅

请求：“看看这个动画的滤镜和收尾是不是太重了，先别改，也别生成音频。”

观察是否只读实际素材、用具体时码评估介质与内容、辨别需要的持续质感和短促强调；不运行制作流程、不动源文件、不以固定效果次数或 PSNR 给审美打分。
