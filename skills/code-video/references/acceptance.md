# 编码成片验收

分别记录技术与内容检查。用户只要求局部修复时验受影响范围；要交付成片时看最终 MP4，不能用旧版截图、计划、receipt 或源代码自检代替。

## 技术与转写检查

使用 [verify-video.py](../scripts/verify-video.py) 或当前工程的等价检查，确认：

- 实际视频流、预期的音频流、宽高、fps、帧数、可选章节轨（`--expect-chapters`）与时长；声明的预期与最终资产一致。多片合并重写章节时，FFmpeg 须同时传 `-map_metadata` 与 `-map_chapters`，并用 `--expect-chapters` 强校验（仅 `-map_metadata` 会静默继承首片旧章节）。
- 完整解码成功，不只读取头部 metadata。音视频时长偏差按帧和编码容器精度解释；不能靠 `-shortest` 掩盖拼接错误。含浏览器录屏素材时加跑 `--check-flicker` 扫描全帧单帧/短突发闪屏及 `#808080` 灰边缩框帧。
- 有声音的任务检查实际编码音轨，不是只看合成源 WAV；音轨非意外静音、峰值和可懂度符合用途。逐句 TTS 干声切分严禁使用偏激进的 `silenceremove -46dB` 吃尾音，建议在合成或验收时结合 `--sentence-timeline` 校验每句末 50ms 电平自然衰减；当运行环境具备本地或已授权的语音识别工具时，从编码后的 MP4 提取音轨转写文本，并用 `--transcript-file` 与 `--expected-text-file`（或逐句核对）检查是否发生漏句、尾部截断或整段乱码。
- 页面错误、资源请求失败、排版越界告警、替代字体、输出覆盖、残留自有进程等明确问题被处理。

工具度量与 ASR 文本覆盖率均不等于真人试听。实际未听声音时写明未执行人工耳听，不根据音量、provider boundary 或 ASR 召回率通过便宣称音色一致性、多音字自然度、语调韵律或混音通过。

## 关键动作与实际帧

从编码成片独立抽取 `t = 0` 首帧、重要动态变形中途帧（如条块伸展与转场时刻）及各幕终态帧。接触表只辅助定位，关键帧逐张看原尺寸；拼图出现重影时回看单帧，先排除拼图布局问题。

逐时码回答：谁在做什么，因为什么条件，数量或关系怎么变，为什么得到这个结果。保持实体身份、路径、颜色和标签可追踪；旁白没有建立对象时不提前揭示结论。字幕暂时隐藏后仍应看出主要行动。

检查主图、底部要点条、字幕与页脚的安全间距，确认中途帧无未裁切文字溢出、无外部截图拉伸变形。源 PNG 精确值与有损视频色差区分，不把压缩视频称为逐像素无损。

定量模型显示假设、单位、分母及可改变判断的边界；来源和实测限制可核对。可用故事作隐喻，不能将情节当研究证据。像素运动、PSNR 与亮度用于定位故障，不能给审美或理解效果打伪精确分数。

## 复核与记录

用户要求成片 review 时，让独立审阅者看当前编码 MP4、实际音轨及必要源码；明确其是否听到声音。只读源码或局部审阅不自动生成缺失的影片，明确成片未验证即可。记录影片版本或 SHA、具体时码、问题、修复与重编后的回归，不把旧版缺陷抹成从未发生。

简短验证记录可以包含：

```text
Artifact: 当前 MP4 与版本/摘要（及配套字幕/章节）
Technical: 参数、完整解码、音轨峰值/均值、章节与转写覆盖核对结果
Content: 首帧、过渡中途帧与终态关键时码，对象动作、事实与限定出处
Audio listening: 真人试听范围 / 仅执行客观电平与 ASR 转写核验（未人工耳听）
Fix and regression: 缺陷时码、修改范围、重编后的回归结果
Not checked: 人类学习效果、人工耳听审阅或其他未运行环境
```

文件齐全、源码编译成功或静态终态帧正常不能证明成片全过程正确。学习效果需要实际观察，不从上述技术检查推出。发布、上传或自动运行属于相应任务授权，验收本身不扩大范围。
