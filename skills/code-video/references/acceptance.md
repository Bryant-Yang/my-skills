# 编码成片验收

分别记录技术与内容检查。用户只要求局部修复时验受影响范围；要交付成片时看最终 MP4，不能用旧版截图、计划、receipt 或源代码自检代替。

## 技术检查

使用 [verify-video.py](../scripts/verify-video.py) 或当前工程的等价检查，确认：

- 实际视频流、预期的音频流、宽高、fps、帧数与时长；声明的预期与最终资产一致。
- 完整解码成功，不只读取头部 metadata。音视频时长偏差按帧和编码容器精度解释；不能靠 `-shortest` 掩盖拼接错误。
- 有声音的任务检查实际编码音轨，不是只看原 WAV；音轨非意外静音、峰值和可懂度符合用途。有意无声的产物明示，不伪装成配音成功。
- 页面错误、资源请求失败、替代字体、输出覆盖、残留自有进程等明确问题被处理。

工具度量不等于试听。实际未听声音时写未试听，不根据音量、provider boundary 或 ASR 正确便宣称音色、读音和混音通过。

## 关键动作与实际帧

从编码成片独立选择每个重要动作的前、中、后和首尾时点。接触表定位，关键帧逐张看原尺寸；拼图出现重影时回看单帧，先排除拼图布局问题。

逐时码回答：谁在做什么，因为什么条件，数量或关系怎么变，为什么得到这个结果。保持实体身份、路径、颜色和标签可追踪；旁白没有建立对象时不提前揭示结论。字幕暂时隐藏后仍应看出主要行动。

检查主图与字幕边界、字形、行数、安全区和观看尺寸。颜色、数量、尺寸等不变约束检实际主体内部和边界；一处中心像素或 bbox 正确不能排除中途覆盖。源 PNG 精确值与有损视频色差区分，不把压缩视频称为逐像素无损。

定量模型显示假设、单位、分母及可改变判断的边界；来源和实测限制可核对。可用故事作隐喻，不能将情节当研究证据。像素运动、PSNR 与亮度用于定位故障，不能给审美或理解效果打伪精确分数。

## 复核与记录

用户要求成片 review 时，让独立审阅者看当前编码 MP4、实际音轨及必要源码；明确其是否听到声音。只读源码或局部审阅不自动生成缺失的影片，明确成片未验证即可。记录影片版本或 SHA、具体时码、问题、修复与重编后的回归，不把旧版缺陷抹成从未发生。

简短验证记录可以包含：

```text
Artifact: 当前 MP4 与版本/摘要
Technical: 参数、完整解码、音轨结果
Content: 关键时码、对象与动作、事实和限定
Audio listening: 已执行的范围 / 未执行
Fix and regression: 缺陷时码、修改、当前编码结果
Not checked: 人类学习效果、其他未运行环境或线上状态
```

文件齐全、源码编译成功或页面 HTTP 正常不能证明成片正确。学习效果需要实际观察，不从上述技术检查推出。发布、上传或自动运行属于相应任务授权，验收本身不扩大范围。
