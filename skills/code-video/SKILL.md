# 代码视频制作

让每个关键镜头表现可观察的行动、关系变化或叙事后果，再把画面与实际音轨做成可播放、可复现的成片。保留用户已有工程、声音和风格；从问题选择画法，不把一次成功案例扩展成固定分镜或统一皮肤。

## 按任务读取

- 创作、改视觉或改节奏：读 [视觉叙事](references/visual-storytelling.md)。
- 编写、渲染或修复 Canvas/p5 工程：读 [Canvas 制作管线](references/canvas-pipeline.md)。
- 用户指定 HyperFrames，或已有画布确需接入它的时间轴与导出：读 [HyperFrames 桥接](references/hyperframes-bridge.md)。现有渲染器可完成目标时直接复用，不为使用桥接而迁移。
- 交付或验收视频：读 [成片验收](references/acceptance.md)。只做审阅、脚本或技术局部修复时，完成该范围，不自动制作整片。

## 制作流程

1. 从用户的用途、实际材料和现有工程确定要交付什么。优先复用已有音轨、资产、渲染器和工具；缺少会改变结论、预算或授权的信息时再问。软件安装、在线生成、上传或发布分别遵循当前授权，skill 本身不授予这些权限。
2. 写一份短 brief：观众要理解的问题或故事、关键实体、条件、行动与可见后果，目标尺寸、帧率和声音来源。实证与引用可核对；明确假设下的算术展示假设和步骤。数字、材质或情节不能冒充实测。
3. 先渲染核心关键帧及关键变化终态，检查对象关系、身份、实际字体、字幕分区和目标屏幕的可读性，再扩展动作。解释需要同一对象移动时，保持可追踪的路径，不用切换标题卡代替过程。
4. 确定实际声音后安排事件。音乐用实际拍点，旁白用真实分段、provider boundary 或音频对齐时点；已有录音先核对文本和时长。保存 cue 来源及拼接偏移。按字数插值和手调时点标为编辑估计，不称为真实词边界或声学对齐。
5. 画面按固定输入和 t 计算，不依赖播放历史、墙钟或未播种随机数。字体、脚本和素材准备好后才声明 ready；测试关键动作前、中、后及乱序 seek。源码、资产或时间轴改变后失效旧帧缓存。
6. 按所选路线输出成片，再审实际编码视频。检查对象、条件、数量、动作与旁白是否一致；技术检查与内容审阅分开。明确问题修复后重编并复查相应时码。

## 工具与输出

优先用工程的成熟渲染器。没有可用导出工具且画布满足渲染契约时，可用本 skill 的 [render-canvas.mjs](scripts/render-canvas.mjs)；它读取已有依赖，使用本次独有的帧目录，不安装软件或复用未知旧帧。最小 [Canvas 样板](assets/canvas-starter/studio.html) 只演示接口，不是成片布局或故事模板。

交付用户要求的 MP4，并保留可复现的画面源文件、实际使用的音轨与时间轴。附一份简短验证记录，包含具体时码、检查结果和未执行项。资产与来源记录随工程保存，不默认添加作者、宣传、长片尾或额外交互网页。

技术验证可使用 [verify-video.py](scripts/verify-video.py)。脚本验证可播放性和明确参数，不证明叙事、机制、审美、读音或学习效果。用户要求成片 review 时交由独立审阅者看实际 MP4 与相关源码；只查看源图不能称为成片审阅。只读源码或局部审阅按指定范围完成，没有现成 MP4 时明确成片未验证，不自动生成新片。

## 完成标准

完成用户要求的产物与范围。交付视频时，必要技术检查通过，关键动作和文字在实际编码成片中成立；局部修复或只读审阅时，只确认该范围有证据支撑的结果。验证记录明确区分通过、失败、未检查，未试听不称为声音验收。原有工作和未授权的外部状态保持完整；修复明确缺陷后再交付，不以文件齐全或静态图好看替代成片验收。

维护与独立试读使用 [评审场景](evals/scenarios.md)；这些是输入和判据，不是预先通过的模型基准。本包测试范围见 [skill 验收记录](evals/acceptance.md)，不替代每部影片的验收。
