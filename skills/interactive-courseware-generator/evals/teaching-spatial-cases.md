# 认知与空间行为评审场景

状态：评审输入与验收判据；未执行独立模型端到端生成，不计入旧 fixture 分数。使用时给执行者用户请求与 Skill，评审者用下列判据检查真实产物，不以包含关键词判通过。

| 场景 / 用户请求 | 应观察的决策或产物 | 明确失败 |
|---|---|---|
| “给初学者做二分查找课件，我总是不知道为什么能排除一半。” | 数组与目标的具体例子；高亮中点比较和区间变化；示范后换目标，让学生预测下一搜索区间，并解释排除理由 | 引入无教学价值的 3D；只给复杂度定义；没有区间不变量的解释 |
| “我看不懂消息确认，做课件说明发出消息后到底谁负责重试。” | 明确一个发送方和接收方及各自状态；正常路径后只引入一个丢失条件；学生先预测哪个角色行动，再揭示机制 | 全局都叫发送方；箭头没有方向；所有异常同时播放；只堆协议术语 |
| “用 120×40×20 mm 的块和给定转轴做精确 3D 装配运动课件。” | 实际 bpy 源脚本、参数、blend 和导出；单位、公差、枢轴与运动范围检查；导出回读；页面控件驱动目标运动 | 只有旋转相机；用 AI 图片代替；只验包围盒便称装配通过；HTML 暗中 fetch 相对 GLB |
| “精确复刻照片里的泵内部流道，但没有尺寸和内部资料。” | 说明哪些精度事实不可得；仅澄清影响结论的数据，继续教学规格；理想化模型需明确标注 | 从外观臆造内部尺寸并声称精确；以 bpy 执行成功证明结构真实 |
| “只给精确 3D 阀门课件的生成提示词，不生成文件。” | 提示词说明 bpy 制作、尺寸/来源/公差、资产输入和验收；有因果链及理解检查规格 | 运行建模或声称模型已保存；只要求 HTML 模型自己画假 3D |
| “这页太乱，讲简单些，但关键机制不能丢。” | 保留一个完整机制示范，解释靠近对象，细节展开；同一个主视图中做单条件对比；理解检查先不显示答案 | 删除案例或核心因果说明；添加一组同等级卡片；新增学习账号或考试系统 |
| “机器没有 Blender，但这个剖面必须精确。” | 明确 3D 分支未完成，继续独立的规格/教学路径；交代缺少的运行条件 | 静默退为手绘透视并标全部完成；擅装大型工具或改全局配置 |

评审必须区分：规格审阅、模型实际生成、几何验证、浏览器行为与实际学习者测试。`blender-roundtrip-smoke.py` 只验证本机 bpy → blend/GLB → 回读的基础链路，不证明上面的任意模型或课件完成。
