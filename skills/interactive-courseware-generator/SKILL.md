# 交互式课件生成器

## 能力边界

把教学概念变成可运行的交互式网页。核心合同是：让学生通过一个明确操作观察可见变化，比较典型状态，从而理解因果关系，并知道这个知识在真实场景中解决什么问题、怎样使用。

按学习目标选择交付粒度：一个因果模型优先做成单页；存在多个不同因果模型或具有先备关系的问题时，做成同一目录下的紧凑课件组。不要把术语数量直接等同于页数。

## 认知与空间表达合同

先根据学习者已知内容建立具体心智模型，再解释机制，最后让学生独立预测和迁移。不能用术语堆叠、播放完动画或点对按钮代替理解。精确 3D 建模必须使用 Blender 的 `bpy`；是否需要 3D 取决于学习问题中的几何、装配、遮挡或空间运动关系，而不是装饰需求。

## 按任务读取资源

- 生成、精简或修复教学解释时读 [认知与理解设计](references/cognitive-design.md)；只修不影响教学的技术故障时不必加载。
- 生成新课件或提示词时读 [生成框架](references/generation-framework.md)。
- 涉及空间结构或运动、需要判断是否精确建模时读 [Blender 建模与交付](references/blender-modeling.md)。
- 用户要求“一套课件”、多页目录、主题/协议入门，或现有页面过于复杂时读 [紧凑课件组框架](references/course-suite-framework.md)。
- 直接构建 HTML，或修改配置、教学动作、宿主桥接时读 [运行协议](references/runtime-contract.md)。
- 生成、修改或验证 HTML 时读 [质量门禁](references/quality-gates.md)。
- PWM 或相近模拟再读 [PWM 示例](references/pwm-example.md)，只借鉴结构，不复制页面设计。
- 迁移到新宿主或判断哪些约束必须保持中性时读 [设计依据](references/design-rationale.md)。

## Workflow

1. 先判断交付粒度，而不是默认拆页：
   - 一个核心问题、一个因果模型：生成单页。
   - 两个以上使用不同因果模型、观察对象或具有先备关系的学习问题：默认生成 2–4 个概念页；综合实验仅在确有整合价值时作为可选末页。
   - 明显超过 4 个独立问题时，先判断能否删减或拆成多个紧凑课件组，不把默认页数当成硬上限。
   - 同一模型的并列档位或对比项放在一页比较，例如 QoS 0/1/2，不为每个取值单独分页。
2. 为整个主题写一句真实任务，再为每页写一个学生问题。优先使用贯穿全套课件的具体案例，避免每页更换故事背景。说明学习者已经知道什么、最可能误解什么，以及怎样通过预测或迁移任务判断理解；按“具体场景与对象 → 正常机制 → 关键对比或异常 → 抽象规则与真实用法”搭建路径。
3. 建立“知识点 → 可调变量 → 控件 → 可观察现象 → 对比状态 → 因果结论”映射。每个变量必须有控件和可见结果；没有教学价值的变量不要暴露。
4. 先写课件规格，再按生成框架实现。把因果链拆成可暂停、可回看的有意义状态，讲清对象、输入、变化原因和结果；新手先看一个完整示范，再逐步撤去提示。选择足以表达机制的二维或三维形式；需要精确 3D 时执行 `bpy` 建模、尺寸与关系断言、导出及页面验证，保留可复现源文件。
5. 默认首屏只承载四件事：一个问题、一个主要操作、一个核心现象、一个结论。命令、完整规则、报文轨迹和边界说明作为清楚命名的次级内容按需展开。
6. 让实际使用进入主线而不是附录：课件主线至少回答“它解决什么问题”和“怎样使用”；涉及开发工具或协议时，给出与当前交互同步的最小真实命令、代码或配置。
7. 在每个概念页和综合实验页内嵌合法 `courseware-config` 并使用稳定 DOM ID。交互页必须能独立运行；需要宿主控制时，再实现运行协议中的四类中性消息。课件组的 `index.html` 是目录页，不强制伪造模拟器配置、控件或可视化。
8. 用户需要教学编排时，基于生成后的真实 DOM 选择器编写 3–8 个讲解/操作步骤；找不到真实目标时用讲解或状态动作，不猜选择器。
9. 对每个概念页和综合实验页运行静态校验器；目录页改做导航与链接检查。从本文件位置解析 `<skill-dir>`，不要假设用户当前目录就是 Skill 目录：

   ```bash
   node <skill-dir>/scripts/validate-courseware.js <courseware.html> --json
   ```

   用户明确批准外部依赖时追加 `--allow-external-dependencies`，并在验证报告中逐项列出。由 `script`、`link`、`img` 等加载的相对资源也属于外部依赖；课件页之间的普通 `<a>` 导航不属于资源依赖。

10. 能使用浏览器时，继续检查桌面与移动布局、启动/暂停/重置、每个变量、所有预设、折叠内容、课程导航和控制台错误。修复失败后重新验证。

示范阶段保留核心结论；独立练习阶段可先以预测提示替代答案，作答或主动查看解析后再揭示结论。仅修技术故障时按受影响范围验证，不借新增教学规则重做无关内容。

## 低干扰表达合同

- 标题用学生真正要回答的问题，不用抽象章节名充当主标题。
- 每页只有一个视觉焦点；如使用视觉强调的主按钮，最多突出一个，主要操作也可以是直接操控。暂停、重置作为弱化的辅助操作。
- 控制区通常只暴露 1–3 个直接影响结论的变量。预设用于形成典型对比，不重复堆一套同义控件。
- 指标只保留能解释因果的 1–3 项；不要把课件做成监控仪表盘。
- 避免连续使用“目标卡、场景卡、提示卡、指标卡、解释卡”。能用一句话或一条分隔线表达，就不再增加容器。
- 次级内容必须容易发现，但默认不与主实验争夺注意力。折叠后仍应保留一句可理解的核心结论。
- 复杂度按学习顺序增长：概念页保持单纯，完整控制台只出现在可选综合实验。

## Output Contract

- **单页直接构建**：在用户指定目录输出 `<slug>.html` 和 `<slug>.verification.md`；未指定目录时使用当前工作区的 `courseware/<slug>/`。
- **紧凑课件组**：在一个目录输出 `index.html`、按学习顺序命名的概念页、每页验证报告和 `README.md`。默认 2–4 个概念页；综合实验为可选末页，而不是必选页。每页仍应自包含，不依赖共享 CSS/JS 才能运行。
- **精确 3D 附件**：直接构建时附 `model/build_scene.py`、建模参数及单位/公差说明、`.blend` 源文件、实际使用的导出资源与几何验证证据；页面仍默认自包含，制作源文件不等于页面运行依赖。具体嵌入与交付规则见 Blender 参考。仅生成提示词时写明这些制作要求，不伪造文件或执行结果。
- **教学动作**：用户需要讲解编排时再输出 `<slug>.actions.json`。宿主控制只启用 HTML 内的消息桥接，不自动要求动作文件。
- **只要提示词**：输出 `<slug>.prompt.md`，包含教学规格、HTML system/user prompt 和教学动作 prompt，不伪造已生成或已验证的 HTML。
- **修改现有课件**：保留用户已有内容，只修改目标行为，并重新运行相关门禁。用户说“太复杂”时先做信息减法与渐进披露，不以删除核心案例和因果反馈换取简洁。

## 硬规则

- 一页只承担一个主要教学问题；一套课件只保留支撑最终任务的最短学习路径。
- 交互必须服务于理解，不做装饰；实际案例必须具体到情境、对象或角色（如适用）、输入或条件、关键机制和可观察结果。
- 默认生成单文件、自包含 HTML；未经用户允许不依赖外部 CDN、远程脚本、网络接口或特定宿主产品。
- 使用普通代码实现状态机、公式、映射、重置和消息路由；不要用运行时 LLM 代替确定性逻辑。
- 关键解释必须能沿因果链回溯；至少用一个不直接泄露答案的预测、解释或迁移任务检验每页核心目标，反馈说明错因。不要把支持这些检查等同于已证明学习效果。
- 精确 3D 不得用 AI 图片、手绘透视或未经尺寸验证的近似网格冒充。`bpy` 只是制作工具，精度还需依据、单位、公差和实际检查；工具不可用时明确阻塞该分支，不悄悄降低精度。
- 模型自检不等于真实验证。报告必须区分 `已通过`、`警告`、`未检查`。
- 不声称学科公式、视觉效果或跨浏览器行为正确，除非做过对应验证。

## Do Not Use

不要将本 Skill 用于静态幻灯片、学期级课程规划、普通网站、教学平台、源码讲解或只需静态信息图的任务；这些请求应交给对应的演示文稿、课程设计、网页开发或分析能力。

## 完成标准

只有同时满足以下条件才称为完成：文件存在；确定性验证无错误；每页的问题、主操作、可见现象和结论清楚；每个变量都有可见因果映射；实际案例与真实用法已进入学习路径；默认界面没有被次级细节淹没；如生成教学动作则只使用真实选择器；验证报告披露浏览器、视觉、认知负担、学科、宿主桥接和外部依赖检查状态。

还需满足：认知路径没有跳过必要机制，理解检查对应学习目标并提供错因反馈；精确 3D 分支完成可复现建模、关键几何/运动关系检查和实际展示验证。未运行的检查必须披露，不能称为全部验证通过。

紧凑课件组还必须满足：目录顺序可理解；没有按术语过度拆页；页面导航可达；贯穿案例一致；综合实验不重复概念页已有交互，而是要求整合应用。

- 输出合同对比案例见 `evals/output/cases.jsonl`；其中现有结果是 `recorded_fixture`，不能称为模型执行证据。
