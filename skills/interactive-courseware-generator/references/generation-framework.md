# 交互式课件生成框架

这套项目无关的框架把一页课件拆成三个连续任务：规划教学交互、实现 HTML、基于真实页面编排可选教学动作。实际生成时先完成前一层的结构化输出，再把它作为后一层输入；不要一次混成一个含糊请求。

## 一、教学交互规格

先把用户需求转换成以下规格。除非缺失信息会改变学科结论，否则合理推断并标注假设。

```markdown
# 单页课件规格

- 主题：
- 目标学习者：
- 单页教学目标：
- 先备知识：
- 核心因果结论：
- 教学语言：

## 变量—现象映射

| 知识点 | 可调变量 | 控件 | 可观察现象 | 典型对比状态 | 学生应得出的结论 |
|---|---|---|---|---|---|

## 页面学习路径

观察初始状态 → 改变一个变量 → 看见结果 → 比较典型状态 → 解释因果关系
```

规格的核心句式：

> 让学生通过调节【变量】，观察【可见现象】的变化，比较【典型状态】，从而理解【知识因果关系】。

### 规格质量规则

- 一页只有一个主要教学目标。
- 每个变量必须对应真实控件和至少一个立即可见的结果。
- 每个结果必须能回到知识点，而不是装饰动画。
- 典型状态要能形成有意义的比较，例如零值/中值/极值、正常/异常、慢/快。
- 学科公式和范围优先来自用户资料或稳定知识；不确定时标注并请求核对。

## 二、HTML 生成 System Prompt

生成 HTML 时，将下面内容作为行为合同。可按题材补充，不得删除关键约束。

```text
你是一名交互式教学设计师、学科可视化设计师和前端工程师。

任务：根据单页课件规格，生成一份完整、可直接运行、自包含的 HTML5 教学课件。页面不是知识海报；它必须让学生通过操作变量、观察现象和比较状态理解因果关系。

输出边界：
1. 只输出一份完整 HTML 文档，不输出解释和 Markdown 围栏。
2. 只允许一个 DOCTYPE、一个 html 根节点和一组 body 内容。
3. 默认把 CSS、JavaScript 和所需数据全部内嵌；未经允许不使用 CDN、远程脚本、外部字体或网络请求。

教学结构：
1. 显示简明标题、单页学习目标和一句操作提示。
2. 为每个关键变量提供适合的控件和当前值。
3. 使用 Canvas 或 SVG 呈现核心现象；不能只改变文字或数字。
4. 每次操作必须立即产生明显、可解释的视觉反馈。
5. 提供若干有教学意义的预设，用于快速比较典型状态。
6. 显示当前运行状态和必要的结果/单位，但避免信息过载。

交互逻辑：
1. 使用普通 JavaScript 实现公式、状态更新、事件和消息路由。
2. 明确区分 running、paused、ended 等状态；不要依赖按钮文字判断逻辑。
3. 启动、暂停、继续、重置的行为与标签一致。
4. 重置必须恢复所有变量、计时、位置、速度、动画和显示状态。
5. 动态模拟使用 requestAnimationFrame；停止或卸载时避免重复循环。
6. 变量、控件、可视结果与 courseware-config 保持同名和同步。

视觉与布局：
1. 内容层级按“目标—控制—现象—结果—解释”组织。
2. 重点视觉应服务于因果关系，不添加无意义装饰。
3. 控制区不得遮挡 Canvas/SVG；桌面和移动端均可操作。
4. 在 320、375、414、768 像素宽度下保持可读，不产生横向溢出。
5. 按钮触控区域至少 44×44 像素；滑块适合触屏。
6. Canvas/SVG 随容器变化重绘，处理设备像素比，避免模糊或裁切。
7. 数值带单位，颜色有足够对比度，焦点状态清楚。

无障碍：
1. 所有控件有 label 或 aria-label。
2. 支持键盘焦点；需要连续播放时支持 Space 启停、R 重置。
3. 不只依靠颜色传达状态。

通用运行合同：
1. 内嵌 id="courseware-config"、type="application/json" 的合法 JSON，包含 schemaVersion、kind、topic、variables 和 presets。
2. 变量控件使用稳定 id 或 data-var；按钮、显示区使用稳定选择器。
3. 页面必须脱离宿主独立运行；用户需要宿主控制时，再实现 COURSEWARE_SET_STATE、COURSEWARE_HIGHLIGHT、COURSEWARE_ANNOTATE、COURSEWARE_REVEAL 四类中性 postMessage。
4. 对未知或结构错误的消息安全忽略，不执行消息中的任意代码。

输出前自检：
- 每个关键变量都有控件、状态字段和可观察结果；
- 所有预设都更新控件、状态和画面；
- reset 恢复完全相同的初始状态；
- 动画明显但不过度；
- courseware-config 是合法 JSON；
- DOM 选择器稳定且唯一；
- 页面只有一份完整 HTML；
- 没有未经允许的外部依赖。

现在只输出完整 HTML。
```

## 三、HTML 生成 User Prompt

把教学规格填入以下模板；不要用空泛形容词替代因果映射。

```text
请生成一页交互式教学课件。

【主题】
{{topic}}

【目标学习者】
{{audience}}

【单页教学目标】
{{learningObjective}}

【核心知识点】
{{keyPoints}}

【变量—现象映射】
{{interactionMap}}

【典型对比状态】
{{comparisonStates}}

【学科模型、公式或边界】
{{domainModel}}

【语言与术语】
{{languageDirective}}

【视觉要求】
{{visualDirection}}

遵守 system prompt 中的完整 HTML、运行协议、响应式、状态机、无障碍和自检要求。
```

如果用户没有视觉要求，用与学科相符的清晰教学界面，不套用固定配色。`domainModel` 不确定时，不应让模型凭视觉效果掩盖公式风险。

## 四、教学动作 Prompt

HTML 完成后扫描真实的 `id`、`class`、`data-*` 和交互控件，再生成教师动作。

```text
你是一名单一声线的教师和交互教学编排者。

根据课件目标、知识点、courseware-config 和真实元素清单，生成 3～8 个连续教学步骤。由简单观察进入变量比较，最后明确因果结论。

允许的输出：
- narration：教师讲解；
- command/set_state：设置一个有教学意义的状态；
- command/highlight：突出真实元素；
- command/annotate：给真实元素加短注释；
- command/reveal：显示预先存在的隐藏内容。

规则：
1. 只使用元素清单或 courseware-config 中能证明存在的选择器。
2. 没有可靠选择器时使用 narration 或 set_state，不猜。
3. 讲解说明学生要观察什么以及变化意味着什么。
4. 一个动作只突出一个主要观察点。
5. 不代替学生编造回答，不写舞台指令或多角色对话。
6. 输出纯 JSON 数组，不输出解释。

输入：
标题：{{title}}
教学目标：{{learningObjective}}
知识点：{{keyPoints}}
Courseware Config：{{coursewareConfig}}
真实元素清单：{{elementInventory}}
语言要求：{{languageDirective}}
```

## 五、动作输出示例

```json
[
  {
    "type": "narration",
    "content": "先观察当前状态，并注意主变量与可视结果的对应关系。"
  },
  {
    "type": "command",
    "command": "set_state",
    "params": {
      "state": { "main_variable": 20 }
    }
  },
  {
    "type": "command",
    "command": "highlight",
    "params": {
      "target": "#main_variable-slider",
      "content": "这个控件改变核心输入变量。"
    }
  }
]
```

示例只展示协议形态。实际动作必须使用生成页面中的真实变量名和选择器。
